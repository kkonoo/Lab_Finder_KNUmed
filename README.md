# 의과대학 연구실 찾기

경북대학교 융합형 의사과학자 양성사업단의 학부생 연구 인턴십을 위해 만든 페이지예요. 의과대학 학생이 2분 테스트로 자기 연구 스타일을 알아보고, 기초·임상 교수님 연구실을 둘러본 뒤, 인턴십을 온라인으로 신청해요. 테스트와 교수님 소개는 의과학과 [이름북](https://github.com/kkonoo/Biomed_KNUmed/tree/main/namebook)에서, 신청·관리자 화면은 [N2C 홈페이지](https://github.com/kkonoo/n2c)의 공모·신청에서 가져왔어요.

- 연구실 찾기: https://lab-finder-med.knu.ac.kr

## 화면

| › 관리자 | 관리자 구글 계정 넣고 빼기 |

## 연구 스타일 테스트

방법 4가지 × 목표 2가지 = 8가지 유형이에요. 생물정보학(데이터)에 치우치지 않게 네 방법이 똑같은 비중으로 나와요(가능한 답을 모두 돌려 보면 유형마다 12.5% 안팎).

| 방법 | 목표 |
|---|---|
| `W` 🧪 실험 · `E` 🔧 공학 · `D` 💻 데이터 · `P` 🩺 사람·임상 | `Q` 🔍 원리 · `S` 🛠 해결 |

- 방법: 네 가지를 둘씩 한 번씩 맞붙인 6문항에서 가장 많이 고른 것. 둘이 같으면 그 둘을 맞붙인 문항에서 고른 쪽, 셋이 같으면 그중 하나예요.
- 목표: 3문항 중 많이 고른 쪽.
- 추천: 같은 유형 교수님 전부와, 방법이 같고 관심 주제가 겹치는 교수님이 나와요(5분이 안 되면 가까운 분으로 채워요). 순서는 주제가 겹치면 3점 + 그 방법을 고른 횟수(0~3) + 목표가 같으면 1점이에요. 연구 스타일이 비어 있거나 꺼 둔 교수님은 빠져요.
- 질문·유형 설명·관심 주제는 `data/quiz.json`에서 고쳐요. 보이는 교수님이 한 분도 없는 주제는 칩에 안 나와요.

## 교수님 데이터

Firestore `profs`가 원본이에요. 관리자 화면에서 고치면 바로 반영돼요.

- 처음에는 Firestore가 비어 있어서 저장소의 `data/profs.json`(94명)을 보여 줘요. 관리자 화면 › 교수님 › **교수님 목록 가져오기**를 한 번 누르면 Firestore로 옮겨져요. 그다음부터 `data/profs.json`은 Firestore를 읽지 못할 때만 써요(그때는 끈 교수님도 보이고 고친 내용도 안 보여요).
- 사진은 저장소 `photos/`의 파일(가져온 분)이거나, 관리자 화면에서 고른 사진을 300×400 JPEG로 줄여 문서 안에 넣은 것(새로 고른 분)이에요.

`data/profs.json`을 만들 때 가져온 곳 (2026년 11월):

- **기초 66명**: [경북의대 라운지](https://github.com/kkonoo/KNUmed_lounge)의 기초교실 명단(이름·교실·직위·사진).
  - 38명은 이름북 소개를 그대로 썼어요. 라운지의 연구 소개(연구 질문·축·발자취)는 교수님용이라 학생에게 어려워서 가져오지 않았어요.
  - 8명(이원기·양수·정성문·김상욱 의료정보학, 김명남·성기웅·이정현 의공학, 부용출 분자의학)은 라운지가 논문으로 만든 한 줄 초안을 썼어요. `source`가 `draft(확인 필요)`예요.
  - 20명(예방의학·병리학·법의학·의료인문·의학교육학 등)은 아직 소개가 없어요. 이름·교실·사진만 나오고 테스트 추천에서는 빠져요. 관리자 화면에서 채우면 돼요.
- **임상 28명**: 이름북 그대로.
- 연구 스타일은 소개말을 보고 붙인 초안이라 관리자 화면에서 고쳐도 돼요.

## 처음 설정 (한 번만)

Firebase 프로젝트 `lab-finder-knu`의 웹 앱 설정값은 [`js/firebase-config.js`](js/firebase-config.js)에 들어 있어요. 콘솔(https://console.firebase.google.com → `lab-finder-knu`)에서 아래를 해요.

1. **Authentication** → 시작하기 → 로그인 방법에서 **Google** 사용. 설정 → 승인된 도메인에 `kkonoo.github.io` 추가.
2. **Firestore Database** → 데이터베이스 만들기 → 위치 **asia-northeast3 (서울)**, 프로덕션 모드. **색인**은 만들 필요 없어요.
3. Firestore → **규칙** 탭에 [`firestore.rules`](firestore.rules)를 통째로 붙여 넣고 **게시**. 규칙 파일이 바뀌면 다시 붙여 넣어요.
4. 첫 관리자: Firestore → **데이터** 탭(색인 탭 아님) → 컬렉션 시작 → 컬렉션 ID `admins` → 문서 ID에 관리자 구글 이메일(소문자) → 필드 아무거나 하나(예: `name` = 홍길동, 유형 string). 나머지 관리자는 관리자 화면 › 관리자 탭에서 더해요.
5. 관리자 화면 › 교수님 › **교수님 목록 가져오기**.
6. GitHub 저장소 Settings → Pages → Deploy from a branch → `main` / `(root)`.

학교 도메인(예: `labfinder.knu.ac.kr`)으로 옮길 때는 Authentication → 설정 → 승인된 도메인에 그 주소를 **그대로** 더해요. `knu.ac.kr`만 적어도 모든 `*.knu.ac.kr`에서 로그인이 되지만, 그러면 학교의 다른 사이트도 이 프로젝트로 구글 로그인을 띄울 수 있어서 권하지 않아요. 저장소에는 `CNAME` 파일과 학교 DNS의 CNAME 레코드(`kkonoo.github.io`)가 필요하고, `qr.svg`도 새 주소로 다시 만들어요(아래 개발).

## 데이터는 어디에

| 컬렉션 | 내용 | 읽기 | 쓰기 |
|---|---|---|---|
| `profs/{id}` | 교수님 소개: 이름·직위·교실·기초/임상·한 줄 소개·키워드·링크·담당자·연구 스타일·관심 주제·사진·이메일·`hidden`(끔) | 누구나 | 관리자 |
| `config/notice` | 모집 안내: 회차·신청 받기·제목·소개·안내 항목·문의 메일·개인정보 보유 기간 (없으면 [`js/notice.js`](js/notice.js)의 기본값) | 누구나 | 관리자 |
| `applications` | 신청서: 회차, 이름·학번·학년·연락처·이메일, 트랙, 희망 연구실(3지망까지), 연구 스타일·관심 주제, 지원 동기, 연구 경험, 동의, 상태·메모 | 관리자 | 누구나 새로 내기만(로그인 없음), 관리자는 상태·메모 고치기와 삭제 |
| `admins/{이메일}` | 관리자 (문서 ID = 구글 이메일) | 관리자 | 관리자 (자기 자신은 못 빼요) |

- 연구실 찾기·신청 화면은 `profs`와 `config/notice`를 Firebase SDK 없이 REST로 가볍게 읽어요([`js/data.js`](js/data.js)). SDK는 신청서를 낼 때와 관리자 화면에서만 불러와요.
- 신청은 로그인 없이 받아서 이름·이메일은 확인되지 않은 값이에요. 같은 학생이 두 번 낼 수도 있어요.
- 메일 보내기 기능이 없어서 새 신청 알림과 결과 메일은 나가지 않아요. 관리자 화면에서 확인하고, 신청을 열어 이메일을 누르면 메일 쓰기 창이 열려요.
- 첨부 파일은 받지 않아요(Firebase Storage는 유료 요금제가 필요해서). 지원서 파일이 꼭 필요하면 메일로 받아요.
- 다음 모집 때는 관리자 화면 › 모집 안내에서 회차와 안내를 바꾸고 저장해요. 모집이 끝나면 ‘온라인 신청 받기’를 꺼요.

## 개발

빌드 없이 정적 파일이에요. 저장소 맨 위에서 아무 정적 서버로 열어요(`file://`로 열면 데이터를 못 읽어요).

```bash
python3 -m http.server 8770
```

QR 코드(`qr.svg`)는 주소가 바뀔 때만 다시 만들어요 (`pip install segno`).

```bash
python3 -c "import segno; segno.make('https://kkonoo.github.io/Lab_Finder_KNUmed/', error='m').save('qr.svg', border=0, dark='#262B33', scale=4)"
```

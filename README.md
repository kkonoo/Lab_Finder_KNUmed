# 의과대학 연구실 찾기

경북대학교 융합형 의사과학자 양성사업단의 학부생 연구 인턴십을 위해 만든 페이지예요. 의과대학 학생이 2분 테스트로 자기 연구 스타일을 알아보고, 기초·임상 교수님 연구실을 둘러본 뒤, 인턴십을 온라인으로 신청해요. 구성은 의과학과 [이름북](https://github.com/kkonoo/Biomed_KNUmed/tree/main/namebook)과 같고, 신청·관리자 화면은 [N2C 홈페이지](https://github.com/kkonoo/n2c)의 공모·신청과 같은 방식이에요.

- 연구실 찾기: https://kkonoo.github.io/Lab_Finder_KNUmed/
- 인턴십 신청: https://kkonoo.github.io/Lab_Finder_KNUmed/apply.html
- 관리자: https://kkonoo.github.io/Lab_Finder_KNUmed/admin.html

## 화면

| 화면 | 하는 일 |
|---|---|
| 연구실 찾기 (`index.html`) | 맨 앞에 연구 스타일 테스트(9문항 + 관심 주제), 그다음 표지(인원·가나다 찾아보기·QR)와 교수님 카드(기초 → 임상, 교실 → 이름 순). 휴대폰에서는 카드가 한 줄씩 나와요. 인쇄하면 A4 한 장에 6명씩 (`labfinder.pdf`, 테스트는 빠지고 끈 교수님도 모두 나와요) |

## 연구 스타일 테스트

방법 4가지 × 목표 2가지 = 8가지 유형이에요. 생물정보학(데이터)에 치우치지 않게 네 방법이 똑같은 비중으로 나와요(512가지 답을 모두 돌려 보면 유형마다 12.5% 안팎).

| 방법 | 목표 |
|---|---|
| `W` 🧪 실험 · `E` 🔧 공학 · `D` 💻 데이터 · `P` 🩺 사람·임상 | `Q` 🔍 원리 · `S` 🛠 해결 |

- 방법: 네 가지를 둘씩 한 번씩 맞붙인 6문항에서 가장 많이 고른 것. 둘이 같으면 그 둘을 맞붙인 문항에서 고른 쪽, 셋이 같으면 그중 하나예요.
- 목표: 3문항 중 많이 고른 쪽.
- 추천: 같은 유형 교수님 전부와, 방법이 같고 관심 주제가 겹치는 교수님이 나와요(5분이 안 되면 가까운 분으로 채워요). 순서는 주제가 겹치면 3점 + 그 방법을 고른 횟수(0~3) + 목표가 같으면 1점이에요.
- 질문·유형 설명·관심 주제는 `data/quiz.json`에서 고쳐요. 교수님이 한 분도 없는 주제는 고르는 칸에 안 나와요.

## 고치고 다시 만들기

교수님 내용은 `data/profs.json`만 고치고 다시 만들어요. `index.html`과 `labfinder.pdf`가 새로 생겨요.

```bash
pip install segno
```

```bash
python3 build.py
```

PDF 없이 HTML만 만들려면 `python3 build.py --html`이에요.

`data/profs.json`의 항목 (이름북과 같고, `style`만 두 글자 목록이에요):

| 키 | 내용 |
|---|---|
| `name`, `rank`, `dept`, `kind` | 이름, 직위, 교실, 기초/임상 (기초·임상 순 → 교실 → 이름 순으로 정렬돼요) |
| `line`, `keywords` | 학생용 한 줄 소개, 키워드 3개. `line`이 비어 있으면 카드에 ‘연구 소개를 준비하고 있어요’가 나와요 |
| `links` | 카드 아래 링크 `[주소, 글자]` 목록 |
| `contact` | 담당자 `[이름, 연락처]` (없으면 `null`). 공개 저장소라 웹에도 그대로 보여요 |
| `style` | 연구 스타일 목록, 예: `["WQ"]`, `["WS", "ES"]`. 비어 있으면 테스트 추천에서 빠져요 |
| `topics` | 관심 주제 키 (`data/quiz.json`의 `topics`) |
| `photo` | 사진 경로 (3:4) |
| `email` | 카드에 보이는 이메일 (없으면 `""`) |
| `source` | 소개말의 근거 (화면에는 안 나와요) |

- **기초 66명**: [경북의대 라운지](https://github.com/kkonoo/KNUmed_lounge)의 기초교실 명단(이름·교실·직위·사진).

  - 20명(예방의학·병리학·법의학·의료인문·의학교육학 등)은 아직 소개가 없어요. 이름·교실·사진만 나오고 테스트 추천에서는 빠져요.

## 인턴십 신청

### 처음 설정 (한 번만)

신청서를 받을 Firebase 프로젝트가 필요해요. 설정 전에는 신청 페이지가 메일 제출 안내만 보여 주고, 관리자 페이지는 설정 안내만 보여 줘요.

1. [Firebase 콘솔](https://console.firebase.google.com)에서 새 프로젝트를 만들어요(애널리틱스는 꺼도 돼요).
2. **Authentication** → 시작하기 → 로그인 방법에서 **Google** 사용. 설정 → 승인된 도메인에 `kkonoo.github.io` 추가.
3. **Firestore Database** → 데이터베이스 만들기 → 위치 **asia-northeast3 (서울)**, 프로덕션 모드. **색인**은 만들 필요 없어요(복잡한 검색을 하지 않아요).
4. Firestore → 규칙 탭에 [`firestore.rules`](firestore.rules)를 그대로 붙여 넣고 **게시**. 규칙을 고치면 다시 붙여 넣어요.
5. 첫 관리자: Firestore → **데이터** 탭(색인 탭 아님) → 컬렉션 시작 → 컬렉션 ID `admins` → 문서 ID에 관리자 구글 이메일(소문자) → 필드 아무거나 하나(예: `name` = 홍길동, 유형 string). 나머지 관리자는 관리자 페이지의 ‘관리자’ 탭에서 더해요.
6. 프로젝트 설정 → 내 앱 → 웹 앱 추가 → 나오는 `firebaseConfig` 값을 [`js/firebase-config.js`](js/firebase-config.js)의 `null` 자리에 넣어요. 이 값은 공개돼도 괜찮아요. 데이터를 지키는 건 규칙이에요.
7. GitHub 저장소 Settings → Pages → Deploy from a branch → `main` / `(root)`.

학교 도메인(예: `labfinder.knu.ac.kr`)으로 옮길 때는 Authentication → 설정 → 승인된 도메인에 그 주소를 **그대로** 더해요. `knu.ac.kr`만 적어도 모든 `*.knu.ac.kr`에서 로그인이 되지만, 그러면 학교의 다른 사이트도 이 프로젝트로 구글 로그인을 띄울 수 있어서 권하지 않아요. 저장소에는 `CNAME` 파일과 학교 DNS의 CNAME 레코드(`kkonoo.github.io`)가 필요해요.

### 데이터는 어디에

| 컬렉션 | 내용 | 읽기 | 쓰기 |
|---|---|---|---|
| `applications` | 신청서: 회차, 이름·학번·학년·연락처·이메일, 트랙, 희망 연구실(3지망까지), 연구 스타일·관심 주제, 지원 동기, 연구 경험, 동의, 상태·메모 | 관리자 | 누구나 새로 내기만(로그인 없음), 관리자는 상태·메모 고치기와 삭제 |
| `admins` | 관리자 (문서 ID = 구글 이메일) | 관리자 | 관리자 (자기 자신은 못 빼요) |
| `config/labs` | 보여 줄 교수님: `off` = 끈 교수님 이름 목록 (없으면 모두 보여요) | 누구나 (연구실 찾기·신청 화면이 SDK 없이 REST로 읽어요) | 관리자 |

- 로그인 없이 받아서 이름·이메일은 확인되지 않은 값이에요. 같은 학생이 두 번 낼 수도 있어요.
- 메일 보내기 기능이 없어서 새 신청 알림과 결과 메일은 나가지 않아요. 관리자 화면에서 확인하고, 신청을 열어 이메일을 누르면 메일 쓰기 창이 열려요.
- 첨부 파일은 받지 않아요(Firebase Storage는 유료 요금제가 필요해서). 지원서 파일이 꼭 필요하면 메일로 받아요.
